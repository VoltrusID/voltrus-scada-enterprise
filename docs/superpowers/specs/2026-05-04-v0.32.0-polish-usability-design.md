## 1. Theme System (Light/Dark Toggle)

**Track:** 1 (Frontend foundation)

### Backend
- `GET/PUT /api/v1/settings/ui-theme` — persist theme preference per user
- Store in `users` table: `ui_theme TEXT DEFAULT 'dark'`
- Values: `"dark"` | `"light"`

### Frontend
- Extend existing CSS custom properties in `index.css`
- Two theme sets under attribute selectors:
  - `[data-theme="dark"]` — current dark theme values (unchanged)
  - `[data-theme="light"]` — new industrial grey/blue theme:
    - Background: `#E8E8E8` (light grey)
    - Surface/cards: `#FFFFFF`
    - Text primary: `#1A1A1A`
    - Text secondary: `#666666`
    - Accent: `#1A73E8` (industrial blue)
    - Status ok: `#4CAF50` (green)
    - Status fault: `#E53935` (red)
    - Status warning: `#FF9800` (orange)
    - Border: `#CCCCCC`
- `ThemeContext` React context wraps app, reads from localStorage + backend
- Toggle component in top nav bar (sun/moon icon)
- Apply via `document.documentElement.setAttribute('data-theme', value)`
- No page reload required

### Files
- `client/src/index.css` — add light theme variables
- `client/src/contexts/ThemeContext.tsx` — new
- `client/src/components/ThemeToggle.tsx` — new
- `src/api/settings.rs` — add ui-theme endpoints
- `src/storage/settings.rs` — persist theme preference

## 2. Colorblind-Friendly Indicators

**Track:** 1 (Frontend foundation)

### Design
Replace all status indicators that rely on color alone with shape+color combinations:

| Status | Shape | Color (dark theme) | Color (light theme) |
|--------|-------|--------------------|---------------------|
| ok/running | Circle (filled) | `#4CAF50` | `#4CAF50` |
| fault/alarm | Triangle (point-up, filled) | `#E53935` | `#E53935` |
| warning | Diamond (filled) | `#FF9800` | `#FF9800` |
| off/stopped | Square (filled) | `#888888` | `#999999` |
| unknown | Question mark circle | `#AAAAAA` | `#777777` |

### Frontend
- `StatusIndicator` component: SVG-based, accepts `status` prop
- Sizes: `sm` (16px), `md` (24px), `lg` (32px)
- Used everywhere: dashboard widgets, device lists, alarm panels, tag browser, asset inventory
- Backward-compatible: existing color-only indicators replaced with `<StatusIndicator>`

### Files
- `client/src/components/StatusIndicator.tsx` — new
- Update all components that render status colors

## 3. Tag Browser with UNS Tree View

**Track:** 2 (Backend + frontend features)

### Backend

#### Tag path model
- Add optional `path` column to data_sources table: `TEXT DEFAULT NULL` (e.g. `"/Site1/AreaA/Unit2/Pump1"`)
- Migration: `ALTER TABLE data_sources ADD COLUMN path TEXT DEFAULT NULL`
- Tags without a path are auto-grouped under their device name

#### API endpoints
- `GET /api/v1/tags/tree` — returns hierarchical tree structure:
  ```json
  {
    "name": "Site1",
    "children": [
      {
        "name": "AreaA",
        "children": [
          { "name": "Unit2", "children": [
            { "name": "Pump1", "children": [
              { "id": 42, "name": "PMP001_RUN", "value": true, "type": "tag" }
            ]}
          ]}
        ]
      }
    ]
  }
  ```
- `?search=term` — filter tags across all tree levels
- `PUT /api/v1/tags/{id}/path` — update tag's hierarchy path

#### Tag naming enforcement
- `GET/PUT /api/v1/settings/naming-convention` — configure naming regex per project
- Built-in ISA-5.1 template: `{TYPE}{NNN}_{DESCRIPTOR}` → regex: `^[A-Z]{2,4}\d{3}_[A-Z0-9_]+$`
- Custom templates: user provides regex + description
- Tag create/update endpoints validate against active convention, return 400 with hint if non-compliant

### Frontend
- `TagBrowser` component with collapsible tree nodes
- Built with recursive `<TreeNode>` components
- Drag-and-drop via HTML5 drag API: drag tag node → drop on dashboard canvas → create widget
- Right panel: tag details (current value, quality, timestamp, device, alarm config, path)
- ISA-5.1 naming hint shown inline on tag create/edit forms
- Search bar with instant filter (debounced, hits API)

### Files
- `src/api/tags_tree.rs` — new
- `src/storage/tags_tree.rs` — new
- `src/models/tags_tree.rs` — new tree structures
- `client/src/TagBrowser.tsx` — new
- `client/src/components/TreeNode.tsx` — new
- `client/src/queries/tagsTree.ts` — new TanStack Query hooks

## 4. i18n (Multi-Language UI)

**Track:** 1 (Frontend foundation)

### Framework
- `react-i18next` + `i18next` + `i18next-http-backend`
- Translation files: `client/public/locales/{lang}/translation.json`
- Languages: `en` (base, always loaded), `id` (Indonesian), `zh` (Chinese Simplified), `de` (German)
- Lazy-loaded: only the active locale JSON is fetched

### Configuration
- Language selector in top-right nav bar (globe icon + dropdown)
- Persisted to `localStorage` key `voltrus-lang` + `PUT /api/v1/settings/ui-lang`
- Date/number formatting via browser `Intl` APIs (no extra library)

### Translation scope
**Translated:** nav labels, button text, form labels, column headers, tooltips, alarm severity labels, device status labels, error messages, section titles
**NOT translated:** tag names, device names, raw error codes, log messages, API responses

### Files
- `client/src/i18n.ts` — new (i18next config)
- `client/public/locales/en/translation.json` — new (extract existing strings)

## 5. Audit Log Search & Filter

### Backend
- Extend `GET /api/v1/audit` with query parameters:

## 6. CSV → SQLite Data Import

**Track:** 2 (Backend + frontend features)

### Backend
- `POST /api/v1/import/csv` — multipart upload
- Request body: CSV file + JSON options:
  ```json
  { "mode": "dry_run" | "merge" | "replace", "delimiter": ",", "tag_column": "name" }
  ```
- Processing:
  1. Parse CSV, auto-detect column types (tag name, value, timestamp, device)
  2. Validate: check tag names exist (merge mode) or don't conflict (replace mode)
  3. `dry_run` returns preview only (no writes)
  4. `merge` updates existing tags with new values
  5. `replace` drops and re-creates (with confirmation)
- Response:
  ```json
  {
    "total_rows": 500,
    "imported": 487,
    "skipped": 8,
    "errors": 5,
    "error_details": [{"row": 42, "message": "Invalid timestamp format"}]
  }
  ```

### Frontend
- `DataImportWizard` component (follows `AssetImportWizard` pattern)
- Steps: Upload CSV → Auto-detect columns (with manual override) → Preview (with errors highlighted) → Import → Report

### Files
- `src/api/import_csv.rs` — new
- `src/storage/import_csv.rs` — new
- `client/src/DataImportWizard.tsx` — new

## 7. Node-RED Project Importer

**Track:** 3 (Independent systems)

### Backend
- `POST /api/v1/import/node-red` — accepts `flows.json` file upload
- Parser walks flow JSON and converts Node-RED nodes to Voltrus entities:

| Node-RED Node | Voltrus Entity | Notes |
|---------------|----------------|-------|
| `modbus-read` | Modbus device + tags | Register address, unit ID, polling rate |
| `modbus-write` | Modbus device + writable tags | |
| `mqtt in` / `mqtt out` | MQTT config + tags | Topic mapping |
| `function` | Flow engine rule (flagged manual) | JS can't auto-convert to WASM |
| `ui_gauge` / `ui_chart` / `ui_text` | Dashboard widgets | Best-effort layout mapping |
| `trigger` / `delay` / `switch` | Flow engine nodes | |
| `inject` / `debug` | Skipped with warning | Development-only nodes |
| Custom palette nodes | Skipped with warning | Unknown node types |

- Response:
  ```json
  {
    "converted": { "devices": 3, "tags": 42, "dashboard_widgets": 12, "flow_rules": 5 },
    "warnings": [
      { "node_id": "abc123", "type": "function", "message": "Function node requires manual conversion" }
    ],
    "skipped": [
      { "node_id": "def456", "type": "exec", "message": "exec nodes not supported (security)" }
    ]
  }
  ```
- Also accepts optional `package.json` for project metadata

### Frontend
- `NodeRedImportWizard` component
- Steps: Upload flows.json → Conversion preview (show node type mappings, warning badges) → Select which items to import (checkboxes) → Import → Report

### Files
- `src/api/import_nodered.rs` — new
- `src/import_nodered/` — new module directory
  - `mod.rs`
  - `parser.rs` — JSON parser for flows.json
  - `converter.rs` — node-to-voltrus entity mapping
- `client/src/NodeRedImportWizard.tsx` — new

## 8. Embedded MQTT Broker (rumqtt)

**Track:** 3 (Independent systems)

### Backend
- Embed `rumqtt` broker inside the Voltrus binary via `rumqttd` crate
- New `src/mqtt_broker/` module directory:
  - `mod.rs` — broker lifecycle (start/stop/reconfigure)
  - `config.rs` — broker configuration structs
  - `auth.rs` — optional username/password authentication
- Configuration in `config.yaml`:
  ```yaml
  mqtt_broker:
    enabled: false
    port: 1883
    max_connections: 100
    auth:
      mode: "none"  # "none" | "config"
      users: []     # [{ username: "...", password: "..." }]
  ```
- API endpoints:
  - `GET /api/v1/mqtt-broker/status` — running, uptime, connected clients, message count
  - `PUT /api/v1/mqtt-broker/config` — update broker config (restarts broker if running)
  - `POST /api/v1/mqtt-broker/start` — start broker
  - `POST /api/v1/mqtt-broker/stop` — stop broker
- License gate: Starter+ (`require_tier(starter)`)
- Broker runs in a background tokio task, shares the same process

### Frontend
- `MqttBrokerPanel` component:
  - Enable/disable toggle
  - Port configuration
  - Auth mode selector (none / username+password)
  - Connected clients table (client ID, address, subscriptions, messages sent/received)
  - Status indicator (running/stopped/error)
- When adding MQTT devices, hint that `localhost:1883` points to embedded broker

### Files
- `src/mqtt_broker/` — new module directory
- `src/api/mqtt_broker.rs` — new
- `src/storage/mqtt_broker.rs` — new (broker config persistence)
- `client/src/MqttBrokerPanel.tsx` — new
- `client/src/queries/mqttBroker.ts` — new TanStack Query hooks
