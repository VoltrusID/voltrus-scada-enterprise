**Date:** 2026-05-03
**Status:** Approved
**Tier:** Enterprise ($999)
**Timeline:** 6-8 weeks

## Goal

Open the electric utility vertical. DNP3 (IEEE 1815) is the standard protocol for power utilities — substations, grid monitoring, SCADA master stations. Voltrus becomes a DNP3 master that polls outstations (RTUs, IEDs, relays) for real-time data and sends control commands.

## Design Decisions

| Decision | Choice | Rationale |
|---|---|---|
| DNP3 crate | Build native Rust driver | Design Principle #2: own the protocol stack. No external licensing dependency. |
| DNP3 scope | Full master station | Read all input types, class polling, frozen counters, control outputs, secure auth later |
| Architecture | Layered protocol stack | Matches IEEE 1815 spec structure. Testable per-layer. Extensible. |
| Auto-discovery | Network subnet scan | Probe IP:port range for DNP3 link-layer responses. Same UX as Modbus auto-discovery. |

## Backend — DNP3 Protocol Stack

### Module Structure

```
src/dnp3/
├── mod.rs              — Public API: poll_dnp3_device(), write_dnp3_tag(), scan_network()
├── datalink.rs         — Frame encoding/decoding, CRC-CCITT, addressing
├── transport.rs        — Segment reassembly for multi-segment ASDUs
├── application.rs      — ASDU encoding/decoding, object headers, qualifiers
├── master.rs           — High-level master session (connect, poll, write, freeze)
├── objects.rs          — DNP3 data object library (Group 1-44 variants)
└── discovery.rs        — Network scanning for DNP3 outstations
```

### Data Link Layer (`datalink.rs`)

- Frame format: start bytes (0x0564), length, control, destination, source, CRC-CCITT
- Master/outstation addressing: configurable 16-bit data link addresses
- Link reset sequence: master sends RESET_LINK_STATES, outstation responds
- Keep-alive: optional link status requests

### Transport Layer (`transport.rs`)

- Handles ASDUs larger than 249 bytes (data link payload limit)
- Segments: FIR (first) and FIN (final) bits, sequence number
- Reassembly buffer for incoming multi-segment ASDUs

### Application Layer (`application.rs`)

- ASDU structure: function code, internal indications (IIN), sequence number, object headers
- Request function codes: READ, WRITE, SELECT, OPERATE, DIRECT_OPERATE, FREEZE, FREEZE_AT_TIME
- Response handling: solicited (data), unsolicited (outstation-initiated), error responses
- Object headers: group, variation, qualifier code, start/stop or count-based addressing

### Data Object Library (`objects.rs`)

DNP3 point types and their Voltrus mapping:

| DNP3 Group | Variation | Description | Voltrus Type |
|---|---|---|---|
| Group 1 | Var 1/2 | Binary Input | f64 (0.0/1.0) |
| Group 10 | Var 1/2 | Binary Output Status | f64 (0.0/1.0) |
| Group 12 | Var 1 | Control Relay Output Block | f64 (0.0/1.0) |
| Group 20 | Var 1-6 | Counter Input | f64 |
| Group 21 | Var 1-12 | Frozen Counter | f64 |
| Group 30 | Var 1-6 | Analog Input | f64 |
| Group 32 | Var 1-5 | Analog Output Status | f64 |
| Group 40 | Var 1-4 | Analog Output Block | f64 |
| Group 41 | Var 1-4 | Analog Output Event | f64 |

### Master Session (`master.rs`)

`Dnp3MasterSession` — wraps a TCP connection, manages the full DNP3 session lifecycle:

**State machine:** `Disconnected → Connecting → LinkReset → LinkReady → Polling`

**Public API:**
- `connect(ip, port, master_addr, outstation_addr) -> Result<Session>`
- `integrity_poll() -> Result<Vec<Dnp3PointValue>>` — Class 0 scan (all static data)
- `event_scan(class: 1|2|3) -> Result<Vec<Dnp3PointValue>>` — Event scan (changes since last)
- `freeze_counters() -> Result<()>` — Freeze all counter inputs
- `direct_operate(group, index, value) -> Result<WriteResult>` — Control output with ack
- `disconnect()`

**Polling strategy:**
1. On connect: integrity poll (Class 0) — reads all static data
2. Periodic event scan: Class 1 (high priority), Class 2 (medium), Class 3 (low)
3. Configurable intervals per device
4. Unsolicited response handling: accept and process if enabled

**Reconnection:** Exponential backoff (same pattern as Modbus driver, 1s → 30s max)

### Network Discovery (`discovery.rs`)

- Scan a subnet (CIDR notation, /24 max — same as Modbus discovery)
- For each IP:port, send a DNP3 link-layer RESET_LINK_STATES frame
- If response received, outstation is present — extract source address as outstation address
- Return list of discovered outstations with IP, port, data link address
- Concurrency limit: 50 simultaneous probes (same as Modbus)

## Storage Layer

### SQLite Tables

```sql
CREATE TABLE dnp3_devices (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    ip TEXT NOT NULL,
    port INTEGER NOT NULL DEFAULT 20000,
    master_address INTEGER NOT NULL DEFAULT 1,
    outstation_address INTEGER NOT NULL DEFAULT 10,
    enable_unsolicited INTEGER NOT NULL DEFAULT 1,
    integrity_poll_interval_secs INTEGER NOT NULL DEFAULT 300,
    event_scan_interval_ms INTEGER,
    enabled INTEGER NOT NULL DEFAULT 1,
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);

CREATE TABLE dnp3_points (
    id INTEGER PRIMARY KEY,
    device_id INTEGER NOT NULL REFERENCES dnp3_devices(id) ON DELETE CASCADE,
    group_num INTEGER NOT NULL,
    variation INTEGER NOT NULL,
    point_index INTEGER NOT NULL,
    name TEXT NOT NULL,
    display_name TEXT NOT NULL DEFAULT '',
    data_type TEXT NOT NULL DEFAULT 'float64',
    scale REAL NOT NULL DEFAULT 1.0,
    deadband REAL NOT NULL DEFAULT 0.0,
    created_at INTEGER NOT NULL
);

CREATE INDEX idx_dnp3_points_device ON dnp3_points(device_id);
```

### Models (`src/models.rs`)

New types following the existing pattern:

```rust
// DB rows
pub struct Dnp3Device { id, name, ip, port, master_address, outstation_address, ... }
pub struct Dnp3Point { id, device_id, group_num, variation, point_index, name, ... }

// Runtime config for poller
pub struct Dnp3DeviceConfig { id, ip, port, master_address, outstation_address, points, ... }

// Request types
pub struct CreateDnp3DeviceRequest { name, ip, port, master_address, outstation_address, ... }
pub struct UpdateDnp3DeviceRequest { name?, port?, enabled?, ... }
pub struct CreateDnp3PointRequest { group_num, variation, point_index, name, ... }
```

## API Layer

### Endpoints

```
GET    /api/v1/dnp3/devices                    — List all DNP3 devices
POST   /api/v1/dnp3/devices                    — Create device (Enterprise gate)
GET    /api/v1/dnp3/devices/:id                 — Get device + points
PUT    /api/v1/dnp3/devices/:id                 — Update device
DELETE /api/v1/dnp3/devices/:id                 — Delete device + stop poller
POST   /api/v1/dnp3/devices/:id/points         — Add point to device
DELETE /api/v1/dnp3/devices/:id/points/:pid     — Remove point
POST   /api/v1/dnp3/scan                        — Scan subnet for outstations
POST   /api/v1/dnp3/devices/:id/integrity       — Trigger on-demand integrity poll
POST   /api/v1/dnp3/devices/:id/freeze          — Freeze all counters on device
```

### Tier Gating

Every handler checks `state.license_tier.dnp3()` — returns 403 if not Enterprise:
```rust
pub fn dnp3(&self) -> bool {
    matches!(self, LicenseTier::Enterprise)
}
```

### PollerManager Integration

New method following existing pattern:

```rust
pub async fn start_dnp3(&self, config: Dnp3DeviceConfig) {
    // spawn tokio task running dnp3::poll_dnp3_device()
}
```

## Testing

### Unit Tests (per layer)

- `datalink.rs`: Frame encode/decode, CRC calculation, addressing
- `transport.rs`: Segment reassembly, FIR/FIN/sequence handling
- `application.rs`: ASDU encode/decode, object header parsing
- `objects.rs`: Each group/variation value conversion

### Integration Tests

- Master session ↔ outstation simulator over TCP loopback
- Full cycle: connect → integrity poll → event scan → freeze → direct_operate → disconnect
- Reconnection: outstation goes offline, master reconnects with backoff

### Simulator Binary

`src/bin/dnp3-sim.rs` — DNP3 outstation simulator:
- Listens on configurable port
- Responds to link reset, integrity poll, event scan, freeze, direct_operate
- Generates simulated data for all supported point types
- Supports configurable data link address
